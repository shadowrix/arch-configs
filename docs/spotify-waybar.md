# Spotify in Tokyo Glass Dev

The music island sits after the workspaces, before the centered clock. Its three
controls are separate clickable Waybar modules. It keeps its width while paused,
playing or offline; closing Spotify clears the previous track and dims the controls.
Stopped playback displays a neutral status. An offline click does nothing.

Waybar 0.15.0, playerctl 2.4.1, Python 3 and the already installed PyGObject
(`python-gobject` on Arch) are used. Playerctl's GI library exposes MPRIS events
without shell polling. JetBrainsMono Nerd Font supplies the music/control icons.
No packages, web API, account credentials or Spotify SDK are needed.

## Architecture

Standard Waybar labels do not offer a pixel marquee. The helper emits a
character marquee every 250 ms only for long titles, with two-second holds at
both ends. Short titles and controls update only on MPRIS events. Unicode
graphemes are segmented by GLib's existing regex engine, including combining
accents and emoji sequences; wide characters count as two cells. Text and tooltips
are escaped before entering Pango markup, and JSON is generated by Python.
The title has matching minimum/maximum label widths, so fallback fonts cannot
grow the bar. Unusual fallback glyph metrics may still cause GTK ellipsizing.

Each of the four labels runs the same small helper in a separate process. This
uses a little more memory than a shared daemon, but avoids a socket service,
cache files, update signals and their lifecycle problems. Only the title has an
animation timer. No subprocess is spawned for an animation frame.

The PlayerManager detects Spotify appearing and disappearing. Filtering uses the
exact base MPRIS name `spotify`, including instance names such as
`spotify.instance456`; actions select the same instance as the display. The local
desktop client was discovered as `spotify`, alongside `chromium.instance1189`.
Flatpak clients work when they export this Spotify MPRIS identity. Browsers are
deliberately ignored: a Chromium identity cannot reliably prove a tab is Spotify.
There is no automatic fallback to another player.

References: [Waybar custom module options](https://github.com/Alexays/Waybar/blob/master/man/waybar-custom.5.scd)
and [Playerctl's event-driven manager example](https://github.com/altdesktop/playerctl/blob/master/examples/player-manager.py).

## Apply and reload

The repository remains the source of truth. `files.tsv` maps the helper to
`~/.config/waybar/scripts/spotify.py`. Live files remain ordinary copies.

```bash
cd ~/Projects/arch-configs
python3 scripts/theme.py --spotify             # preview only
python3 scripts/theme.py --spotify --apply     # backs up all three targets first
pkill -SIGUSR2 -x waybar
```

This option copies only the Spotify helper, Waybar config and CSS; it does not
apply Hyprland or other theme files. Save the printed backup path. The existing
auto-reload watcher may reload Waybar when the config/CSS are copied.

## Adjustments

- Speed: `STEP_MS` in `waybar/scripts/spotify.py` (higher is slower).
- Repeat pause: `HOLD_SECONDS` in the same file.
- Width: change `WIDTH` in the helper and set both `min-length` and `max-length`
  in `custom/spotify-title` to `WIDTH + 2` (icon and separating space).
- Position: move `group/spotify` within `modules-left`, `modules-center` or
  `modules-right` in `waybar/config.jsonc`. The group retains its own surface.
- Disable: remove `group/spotify` from `modules-left`; leave its definitions for
  later use. Apply and reload as above.

The compact island needs about 280 logical pixels. Your current screen is about
1800 logical pixels wide. Standard Waybar has no CSS media queries for responsive
breakpoints; at widths too narrow for all existing status modules, reduce the
title width or disable the group on that output using Waybar's per-output configs.
Neither monitors nor existing status modules are changed automatically.

## Revert

```bash
python3 scripts/theme.py --spotify --restore backups/<printed-backup-directory>
pkill -SIGUSR2 -x waybar
```

This restores the pre-apply config/CSS and removes the helper if it did not exist.
To retain the rollback as the repository's desired state, copy the restored
config/CSS back to their repository paths, remove the Spotify helper's mapping
from `files.tsv`, and remove its source file. Avoid a full `capture --capture`
while the manifest still references a removed helper. No commit is required.

## Verification

```bash
python3 scripts/test_spotify.py
python3 scripts/test_theme.py
python3 scripts/test_capture.py
git diff --check
```

Spotify tests start a private session bus with fake Spotify and Chromium players.
They exercise MPRIS metadata/status events, play/pause and both skip methods,
instance names, browser isolation, empty metadata, close/restart recovery, Unicode,
escaping, stationary short labels and long-label animation. They never modify
your real Spotify session. Live visual and performance results are recorded
below when available.

Live validation on 2026-10-31: Waybar reloaded successfully; a screenshot confirmed
the island fits beside the workspaces and leaves the centered clock/status island
intact. The desktop client's play/pause changed both playback and the icon; next
and previous changed tracks and metadata. The original track, status and position
were restored afterward. Over a ten-second sample, the scrolling title used
0.1% of one CPU core and the three control listeners used 0.0% each. Combined
proportional memory was about 68 MiB (shared-library-adjusted). These are sample
measurements, not performance guarantees. Closing/restarting Spotify and Unicode
metadata were tested on the isolated bus rather than by terminating the desktop
client. Other physical monitors and manual pointer clicks were not tested.
